# 04 · 조립 가이드

> 오픈 보행 안전 헬멧 프로젝트 문서 · CC BY 4.0 라이선스 · © 2026 씨엘소프트랩(CLSOFTLAB), 이일국 박사

이 가이드는 부품 상자에서 시작해 점검까지 마친 헬멧을 완성하는 과정을 안내합니다. 3D 프린팅 시간을 빼고 하루나 이틀 정도 잡으십시오.

시작하기 전에 [06 · 안전수칙](06-안전수칙.md)을 먼저 읽으십시오. 가장 중요한 규칙은 두 가지입니다.

1. **헬멧 외피(셸)나 충격흡수 스티로폼(EPS) 라이너에 절대 구멍을 뚫거나, 자르거나, 접착제를 바르거나, 녹이지 마십시오.**
   모든 부품은 통풍구에 통과시킨 스트랩과 떼어낼 수 있는 패드로 붙입니다.
2. **헬멧은 보조 도구입니다. 흰지팡이, 안내견, 보행 훈련(O&M)을 절대 대신하지 않습니다.**

## B. 소프트웨어 설치

### B1. Raspberry Pi OS Bookworm 64비트 설치

1. microSD 카드를 컴퓨터에 넣고 Raspberry Pi Imager를 엽니다.
2. **장치(Device):** Raspberry Pi 5.
3. **운영체제(Operating system):** **Debian 12 "Bookworm"** 기반의 *Raspberry Pi OS (64-bit)*.
   Imager의 기본값이 더 새로운 릴리스라면 *Raspberry Pi OS (other)*를 열고 Bookworm
   64-bit (Legacy) 이미지를 고릅니다. 펌웨어 v1.0은 Bookworm 기준으로 만들고 시험했습니다.
4. **저장소(Storage):** 사용할 microSD 카드.
5. **설정 편집(Edit settings)** (OS 사용자 지정):
   - 호스트 이름. 예: `owsh-01`.
   - 사용자 이름과 강력한 비밀번호. 헬멧 주인을 위해 적어 둡니다.
   - Wi-Fi 네트워크와 국가.
   - 시간대와 키보드 배열.
   - 서비스: **SSH** 켜기(비밀번호 또는 키).
6. 카드에 기록한 다음 Pi에 꽂습니다.

### B2. 첫 시작과 업데이트

1. 설정하는 동안에는 Pi를 일반 USB-C 전원 어댑터(5 V 3 A 또는 공식 27 W 어댑터)에 연결합니다.
2. 1–2분 기다린 뒤 컴퓨터에서 접속합니다: `ssh <user>@owsh-01.local`.
3. 시스템을 업데이트합니다.
   ```bash
   sudo apt update && sudo apt full-upgrade -y
   sudo reboot
   ```

### B3. 펌웨어 설치

1. 프로젝트를 받고 `firmware` 폴더로 이동합니다.
   ```bash
   sudo apt install -y git
   git clone <repository-url> owsh
   cd owsh/firmware
   ```
   저장소 URL은 프로젝트 GitHub 페이지에 나온 주소를 사용합니다.
2. 설치 스크립트를 **일반 사용자로** 실행합니다(`sudo`를 붙이지 마십시오. 필요할 때 비밀번호를 묻습니다).
   ```bash
   bash scripts/setup_pi.sh          # add --ocr to also install text reading
   ```
   (`--ocr`을 붙이면 글자 읽기 기능도 함께 설치합니다.)
   이 스크립트가 하는 일은 다음과 같습니다.
   - 시스템 패키지를 설치합니다(카메라, GPIO, `espeak-ng`, `i2c-tools`, `bluez`, `bluez-tools`).
   - `config.txt`에서 I2C를 400 kHz로 켜고 카메라를 켭니다.
   - 가상환경 `firmware/.venv`를 만들고 펌웨어를 설치합니다.
   - AI 모델을 내려받고 자체 시험을 실행합니다.
   - 서비스 두 개를 설치하고 켭니다. **`owsh`**(헬멧 펌웨어)와 **`owsh-bt-agent`**(블루투스
     페어링 에이전트)입니다.
   - 헬멧의 안전하게 끄기 동작으로 Pi 전원을 끌 수 있도록 허용합니다.
3. 재부팅합니다: `sudo reboot`.
4. 서비스 상태를 확인합니다.
   ```bash
   systemctl status owsh owsh-bt-agent
   journalctl -u owsh -f
   ```
   센서를 연결하지 않은 상태에서는 FAULT 메시지가 보입니다. 이것은 예상된 정상 동작입니다(설계서 P4).
   센서가 빠졌는데 "이상 없음"처럼 보여서는 절대 안 되기 때문입니다.

이 가이드에서 펌웨어 도구는 `firmware` 폴더에서 가상환경의 Python으로 실행합니다:
`.venv/bin/python -m owsh.tools.<tool>`.

**글자 읽기(OCR)**는 선택 설치 항목입니다(설계서 §5.5). `--ocr` 없이 설치했다면 원(○) 버튼을 눌렀을 때
"문자 읽기 기능이 설치되어 있지 않습니다."라고 말합니다. 나중에 추가하려면 `.venv/bin/pip install -e ".[ocr]"`를 실행한 뒤
`sudo systemctl restart owsh`를 실행합니다.

**먼저 시뮬레이터로 익혀 보기(선택).** 웹캠이 있는 PC라면 어디서든
`python -m owsh --sim`을 실행해, 하드웨어가 준비되기 전에 진동 패턴과 버튼을 익힐 수 있습니다
([`firmware/README.md`](../../firmware/README.md) 참고).

## C. 책상 위 배선과 첫 점검

1. 전원을 끕니다. [02 · 배선 가이드](02-배선가이드.md)에 따라 모든 부품을 책상 위에서 배선합니다.
2. 아래를 보는 TF-Luna의 주소를 0x11로 바꿉니다([배선 가이드](02-배선가이드.md) 6절 "TF-Luna: I2C 모드와 주소 변경").
3. [배선 가이드](02-배선가이드.md) 7절 "점검"의 항목을 모두 통과해야 합니다.
   `i2cdetect -y 1`에 `10`, `11`, `68`이 보이고, 카메라가 목록에 나오고, 버튼 값이 `hi`/`lo`로 읽히고,
   부팅할 때 모터가 왼쪽 → 가운데 → 오른쪽 순서로 떨립니다.

**책상 위 조립이 모든 점검을 통과할 때까지 다음 단계로 넘어가지 마십시오.** 고장은 헬멧 위의 닫힌 케이스 안보다
책상 위에서 훨씬 찾기 쉽습니다.

## D. 모듈 만들기

각 단계를 시작하기 전에 전원을 끕니다. 나사 규격은 [`hardware/README.md`](../../hardware/README.md)에 정리되어 있습니다.
셀프태핑 구멍은 나사를 한 번 끝까지 박았다가 다시 빼낸 다음 조립합니다.

### D1. 전방 센서 포드 (`front_pod_base`, `front_pod_cover`)

1. **Camera Module 3 Wide**를 카메라 칸에 M2 × 5 나사 4개로 고정합니다. 렌즈는 창을 통해
   10° 아래를 봅니다. 너무 세게 조이지 마십시오. 기판이 깨질 수 있습니다.
2. 무엇이든 닫기 전에 카메라 케이블의 15핀 쪽을 먼저 연결합니다.
3. **S1(전방 TF-Luna)**을 앞쪽 칸에 렌즈가 앞을 향하도록 넣습니다(M2 × 5 나사 2개).
4. **S2(아래쪽 TF-Luna, 0x11 라벨)**를 50° 경사면 칸에 렌즈가 앞쪽 아래를 향하도록 넣습니다(M2 × 5 나사 2개).
5. **렌즈를 가리지 마십시오.** 앞에서 확인합니다. TF-Luna 두 개의 구멍과 카메라 렌즈가 완전히 트여 있어야 하고,
   빗물 차양(rain visor)이 시야 안으로 내려오지 않아야 합니다.
6. 카메라 리본 케이블과 TF-Luna 케이블 2개를 뒤쪽 벽의 케이블 출구로 빼냅니다.
7. `front_pod_cover`를 닫습니다(M2 × 8 나사 4개).
8. 극세사 천으로 렌즈를 닦습니다.

### D2. 메인 케이스 (`main_case_base`, `main_case_lid`)

메인 케이스에는 **Active Cooler를 단 Pi 5, MPU-6050, 상태 LED**만 들어갑니다.

1. Pi 5에 **Active Cooler**를 장착합니다(제품 상자에 든 설명서를 따릅니다).
2. M2.5 × 6 나사 4개로 Pi를 스탠드오프 위에 고정합니다. USB-C 전원 단자, USB-A 포트, 쿨러 배기구가
   각각의 구멍과 맞아야 합니다.
3. **MPU-6050**을 홈에 밀어 넣습니다. 단단히 고정합니다. 낙상 감지는 전체 가속도를 쓰므로 방향은 상관없습니다.
   하지만 헐거운 IMU는 덜걱거리면서 충격처럼 보일 수 있습니다.
4. 3 mm 상태 LED를 뚜껑 안쪽에서 눌러 끼웁니다.
5. 카메라 리본 케이블의 22핀 쪽을 **CAM/DISP 0**에 연결합니다.
6. 책상 위 조립 때와 똑같이 듀폰 선을 연결합니다. 분배선은 감싼 상태로 둡니다. ULN2003으로 가는 선
   (IN1–IN3, 5 V, GND)은 케이스 밖으로 나가 보조 포드로 향합니다.
7. **W4 USB-A 연장 케이블**을 검은색 USB 2.0 포트에 꽂습니다. 소켓 쪽 끝은 뒤쪽 구멍으로 빼냅니다.
8. 뚜껑을 닫습니다(M2.5 × 8 나사 4개). 끼인 선이 없어야 합니다. 쿨러 팬이 자유롭게 돌아야 합니다.
   팬과 뚜껑 사이 틈은 약 1.2 mm뿐입니다.

### D3. 보조 포드 (`aux_pod_base`, `aux_pod_lid`)

뒤통수 쪽에 다는 보조 포드(aux pod)에는 **ULN2003 드라이버**와 **USB 오디오 어댑터**가 들어갑니다.

1. ULN2003 기판을 거치대(cradle)에 넣습니다. 메인 케이스에서 온 선 중 IN1/IN2/IN3(GPIO17/27/22), "+"(5 V),
   "−"(GND)를 연결합니다.
2. 배선 가이드대로 모터 선 3개를 ULN2003에 연결합니다. 모터 선은 **아래쪽 홈**으로 빠져나가
   헬멧 안쪽 쿠션 패드 쪽으로 향합니다.
3. USB 오디오 어댑터를 W4 연장 케이블에 꽂고 레일에 밀어 넣습니다. 헤드셋 단자가 단자 구멍을
   향해야 합니다.
4. 뚜껑을 닫습니다(M2.5 × 8 나사 4개).

### D4. 버튼 모듈 (`button_module`, `button_caps`)

1. 12 mm 스위치 3개를 끼웁니다.
2. **앞에서 뒤로** 이 순서대로 캡을 눌러 끼웁니다: **원(○), 점 1개(B1)**, **세모(△), 점 2개(B2)**,
   **네모(□), 점 3개(B3)**.
3. 선을 연결합니다: B1 → GPIO5(29번 핀), B2 → GPIO6(31번 핀), B3 → GPIO26(37번 핀). 각각 GND도 연결합니다.
   버튼 모듈 기판을 쓴다면 **3.3 V만** 연결합니다.
4. 눈을 감고 손으로 만져 다시 확인합니다. 원은 앞, 세모는 가운데, 네모는 뒤입니다.

### D5. 진동 패드 (`haptic_pad` × 3)

1. TPU 패드마다 코인 모터를 옆에서 하나씩 밀어 넣습니다. 얇은 피부 접촉막이 머리 쪽을 향합니다.
2. 벨크로(찍찍이)의 **갈고리(hook)** 쪽 조각을 홈에 붙입니다.
3. 패드에 라벨을 붙입니다: **L**(M1), **C**(M2), **R**(M3).

## E. 구멍 뚫지 않고 헬멧에 장착하기

> **모든 단계에 적용되는 규칙:**
> - 헬멧 외피(셸)나 충격흡수 스티로폼(EPS) 라이너에 구멍 뚫기, 자르기, 접착제 바르기, 가열하기, 녹이기를 하지 않습니다.
> - 쓸 수 있는 방법은 기존 통풍구에 통과시킨 스트랩, 외피 **바깥** 면에 붙이는 떼어낼 수 있는 3M 듀얼락 패드,
>   그리고 **헬멧 안쪽 쿠션 패드**에 붙이는 벨크로(찍찍이)뿐입니다. 스트랩을 나사, 케이블 타이, 접착제로 대신하지 마십시오.
> - 외피에서 튀어나오는 높이: 전방 센서 포드 **35 mm** 이하, 메인 케이스 **40 mm** 이하, 나머지 모든 모듈 **30 mm** 이하.
>   바깥 모서리는 모두 둥글게 만듭니다. 모듈 아래에 받침 기둥을 세우거나 5 mm보다 큰 틈을 두지 않습니다.

### 모듈별 위치

| 모듈 | 위치 |
|---|---|
| 전방 센서 포드 | 앞 윗부분, 이마 위 가운데 |
| 메인 케이스 | 머리 꼭대기, 정수리 뒤쪽, 긴 변이 앞뒤 방향 |
| 보조 포드 | 뒤통수, 메인 케이스 아래 |
| 버튼 모듈 | 오른쪽 옆면, 귀 위, 아래 테두리 가까이 |
| 진동 패드 | 안쪽 헬멧 쿠션 패드 위: 왼쪽 관자놀이, 이마 가운데, 오른쪽 관자놀이 |

### E1. 외피 청소

장착할 부분을 순한 비누와 물로 씻고 완전히 말립니다. 아세톤이나 독한 알코올 같은 **용제는 쓰지 마십시오.**
많은 헬멧 제조사가 용제가 외피를 약하게 만들 수 있다고 경고합니다. 3M 듀얼락은
15 °C 이상에서 가장 잘 붙고, 약 24–72시간이 지나면 최대 접착력에 이릅니다.

### E2. 새들(받침 패드)

큰 모듈 세 개는 `saddle_pad` 판에서 나온 3 mm TPU 새들(받침 패드)에 각각 올립니다(포드, 케이스, 보조 포드).

1. 새들마다 **양면에** 3M 듀얼락을 붙입니다(또는 벨크로).
2. 새들은 외피 위에 **올려놓기만** 하며, 외피 모양에 맞춰 휘어집니다. 외피에 절대 접착제로 붙이지 마십시오.

### E3. 전방 센서 포드

1. 포드를 새들 위에 눌러 붙입니다.
2. 이마 위, 좌우 가운데에 맞춰 외피 위에 올립니다. 옆에서 봅니다. 헬멧을 평소 자세로
   머리에 썼을 때 전방 LiDAR가 대략 수평이어야 합니다.
3. **20 mm 스트랩 2개**를 끼웁니다. 스트랩 탭 구멍으로 내려 넣고, 헬멧 통풍구를 지나 다시 위로 올라오게 합니다.
   **헐겁지 않게, 하지만 너무 조이지 않게** 채웁니다.
4. 헬멧 안쪽에서 스트랩은 라이너에 **평평하게** 붙어 있어야 하고, 머리 쪽에 꼬임이나 버클이 없어야 합니다.
   헬멧 안쪽 쿠션 패드가 스트랩을 덮습니다.
5. 포드 양 끝에서 새들과 외피 사이의 틈을 확인합니다. 틈이 몇 mm보다 크다면 포드가 다른 반지름에 맞춰
   렌더링된 것입니다. 다시 재고 다시 출력하십시오.

### E4. 메인 케이스

방법은 같습니다. 새들 + 3M 듀얼락 + **통풍구에 통과시킨 스트랩 2개**를 씁니다. 위치는 머리 꼭대기, 정수리 뒤쪽이며
긴 변이 앞뒤 방향을 향합니다. USB-C 구멍과 쿨러 배기구가 스트랩이나 외피에 막히면 안 됩니다.

### E5. 보조 포드

1. 새들 + 3M 듀얼락 + 뒤통수 쪽 통풍구에 통과시킨 스트랩으로, 메인 케이스 아래에 붙입니다.
2. **W4 USB 연장 케이블**과 ULN2003 선을 메인 케이스 뒤쪽 구멍에서 보조 포드까지 짧고 깔끔한 고리 모양으로
   보냅니다. `cable_clip`으로 고정합니다. 손이나 나뭇가지에 걸릴 수 있는 곳에 늘어져 있으면 안 됩니다.
3. 헤드셋 케이블은 보조 포드의 단자 구멍에서 나와 헬멧 옆면을 돌아 헤드셋으로 갑니다.
   얼굴 앞을 가로지르지 않게 합니다.

### E6. 버튼 모듈

1. 짧은 스트랩으로 옆 통풍구에 `strap_anchor`를 고정합니다.
2. 버튼 모듈을 3M 듀얼락과 비스듬한 스트랩 탭으로 붙입니다.
3. 사용자와 함께 확인합니다. 사용자가 오른손으로 더듬지 않고 바로 앞쪽의 원(○)을 찾을 수 있어야 합니다.
4. 모듈이 귀를 누르거나 안경·모자에 걸리면 안 됩니다.

### E7. 진동 패드

1. 헬멧의 떼어낼 수 있는 쿠션 패드에 벨크로의 **고리(loop)** 쪽을 붙입니다. 위치는 **왼쪽 관자놀이**,
   **이마 가운데**, **오른쪽 관자놀이**입니다. 대부분의 쿠션 패드는 원래 갈고리 테이프가 달라붙는 고리형 원단입니다.
2. 패드를 눌러 붙입니다. 충격흡수 스티로폼 라이너에는 절대 접착제로 붙이지 마십시오.
3. 사용자가 헬멧을 써 보게 합니다. 패드 하나하나가 따로, 또렷하게 느껴질 때까지 위치를 조정합니다.
   머리카락, 스카프, 모자는 진동을 약하게 만듭니다. 세기를 올리기보다 패드 위치를 옮기십시오.

### E8. 케이블 정리

1. 카메라 리본 케이블을 `fpc_cover` 안에 넣어 전방 센서 포드에서 메인 케이스까지, 외피 중심선을 따라
   스트랩 아래로 지나가게 합니다. `cable_clip`으로 고정합니다.
2. TF-Luna와 버튼의 듀폰 선도 같은 길을 따라 묶어 보냅니다. I2C 선은 각각 접지선과 꼬아 줍니다.
3. 모터 선은 보조 포드의 아래쪽 홈에서 나와 통풍구를 지나 안쪽으로 들어갑니다. 라이너 가장자리를 따라
   쿠션 패드 아래로 지나가게 해서 피부에 닿지 않게 합니다.
4. 모듈마다 여유 선을 작은 고리 모양으로 조금 남겨 둡니다. 케이블이 당겨져도 커넥터가 빠지면 안 됩니다.
5. 얼굴 앞에 늘어지거나, 귀를 가로지르거나, 턱끈 아래로 지나가는 선이 없어야 합니다.

### E9. 분리형(당기면 빠지는) 전원 케이블

보조배터리는 주머니나 허리 가방에 넣습니다. 케이블이 목에 걸릴 가능성은 절대 없어야 합니다.

1. **자석식 분리형 어댑터**를 Pi의 USB-C 단자에 꽂습니다(또는 케이블이 헬멧을 빠져나오는
   지점에 둡니다).
2. 1.5 m 케이블을 헬멧 뒤쪽에서 등을 따라 주머니나 허리 가방까지 내립니다.
3. **당김 시험:** 헬멧을 책상에 놓고 케이블을 세게 확 잡아당깁니다. 헬멧이 움직이기 전에
   자석 연결부가 먼저 떨어져야 합니다. 헬멧이 대신 끌려온다면 어댑터가 너무 세게 붙어 있는 것입니다. 교체하십시오.
4. 케이블을 목에 감거나, 조일 수 있는 방식으로 옷 사이에 통과시키지 마십시오.

### E10. 최종 기계 점검

- [ ] **외피에서의 높이**(가장 높은 지점을 캘리퍼스로 잽니다): 전방 센서 포드 35 mm 이하, 메인 케이스 40 mm 이하,
      보조 포드, 버튼 모듈, 나머지 모두 30 mm 이하.
- [ ] 어떤 모듈의 새들과 외피 사이에도 **5 mm보다 큰 틈이 없습니다**.
- [ ] **무게:** 헬멧 무게를 다시 잽니다. 늘어난 무게(보조배터리와 빗물받이 제외)가 **380 g 이하**입니다
      (예상값 약 330 g).
- [ ] **균형:** 사용자가 고개를 끄덕여도 헬멧이 앞뒤로 기울지 않습니다.
- [ ] **착용감:** 헬멧이 여전히 수평으로 앉고, 턱끈과 뒤쪽 조절 다이얼이 정상적으로 조절됩니다.
- [ ] **외피나 라이너에 구멍, 절단, 접착제가 없습니다.** 한 번 더 확인합니다.
- [ ] **모서리:** 모든 모듈을 손으로 쓸어 봅니다. 날카로운 모서리, 뾰족한 곳, 풀린 선 끝이 없습니다.
- [ ] **통풍:** 통풍구가 적어도 몇 개는 열려 있습니다.
- [ ] 헬멧 안쪽의 **인증 라벨**을 여전히 읽을 수 있습니다.

## F. 휴대폰 페어링(등록)

헬멧은 **페어링(등록)된 휴대폰**에서 온 명령만, 암호화된 연결로 받습니다(설계서 §8.3).
그렇지 않으면 근처에 있는 누구나 음성 안내를 끄거나 낙차 감지 민감도를 낮출 수 있기 때문입니다.

1. 안드로이드에서는 Chrome, 아이폰에서는 Bluefy 브라우저로 휴대폰 앱을 HTTPS 주소로 엽니다
   ([`app/README.md`](../../app/README.md) 참고).
2. 헬멧을 켭니다. **아직 등록된 휴대폰이 없으면** 페어링은 언제나 열려 있습니다. 휴대폰이 한 번 등록되면
   페어링은 **켤 때마다 처음 2분 동안만** 열립니다.
3. 앱에서 **헬멧 연결** 버튼을 누르고 `OWSH-XXXX`를 고릅니다.
4. 앱이 처음 명령을 보낼 때, 휴대폰이 평소의 시스템 대화상자를 띄웁니다. 예를 들어
   **"OWSH-XXXX와(과) 페어링하시겠습니까?"**와 같이 묻습니다(정확한 문구는 휴대폰 기종과 언어에 따라 다릅니다).
   헬멧에는 화면이나 키패드가 없으므로 PIN은 없습니다. **페어링**을 누릅니다. 화면낭독기가 이 대화상자를 소리 내어 읽어 줍니다.
5. 헬멧이 **"새 휴대폰이 등록되었습니다: <휴대폰 이름>."**이라고 말합니다. 그다음부터는 자동으로 연결됩니다.
6. **휴대폰을 추가하거나 바꾸려면** 헬멧을 다시 켜고 2분 안에 페어링합니다.
7. **등록을 모두 지우려면** Pi에서 `bluetoothctl devices Paired`를 실행한 다음, 기기마다
   `bluetoothctl remove <address>`를 실행합니다.

사용자에게 알려 주십시오. 휴대폰을 등록하지 않았는데 헬멧이 "새 휴대폰이 등록되었습니다"라고 말한다면, 다른 사람이
등록한 것입니다. 등록을 지우고 헬멧을 다시 켜십시오.

## G. 첫 부팅 점검표

실내의 안전한 방에서, 앞을 볼 수 있는 도우미와 함께 합니다. 노트북으로 로그를 지켜봅니다:
`journalctl -u owsh -f`. 항목마다 체크합니다. 아래 음성 안내는 한국어 문구 파일
(`firmware/owsh/i18n/ko.json`)에서 인용했습니다. 실제 음성 문구는 펌웨어 한국어 파일(ko.json)을 따릅니다.

### G1. 시작

- [ ] 보조배터리를 연결합니다. 상태 LED가 켜집니다.
- [ ] 1분쯤 안에 헤드셋에서 "헬멧 준비 완료."와 "이 헬멧은 보조 장치입니다. 흰지팡이나 안내견과 함께
      사용하세요."가 나옵니다.
- [ ] **준비 패턴:** **왼쪽 → 이마 → 오른쪽**으로 빠르게 훑고 지나갑니다(각 100 ms).
- [ ] 이어서 고장(FAULT) 패턴(이마에 아주 빠른 진동 세 번)이 나오지 않습니다. 나온다면 로그를 확인합니다.

### G2. 버튼 (누름이 인식될 때마다 이마에 짧은 `tick`)

- [ ] 원(○) B1 짧게(0.8초 미만): tick, 이어서 글자 읽기(또는 "문자 읽기 기능이 설치되어 있지 않습니다.").
- [ ] 원(○) B1 길게(1.5초 이상): tick, 마지막 안내를 다시 들려줍니다.
- [ ] 약 0.8초에서 1.5초 사이로 누르면 무시됩니다.
- [ ] 세모(△) B2 짧게: tick, 장면 설명.
- [ ] 세모(△) B2 길게: tick, "여기가 어디인지" 안내(휴대폰 앱이 연결되어 있어야 합니다).
- [ ] 세모(△) B2 두 번: tick, 누가 있는지(얼굴) 안내.
- [ ] 네모(□) B3 짧게: tick, 상태 안내.
- [ ] 네모(□) B3 두 번: tick, "음성 안내를 끕니다. 위험 경고는 계속 말합니다." 이어서 세모(△) B2를 짧게 누릅니다.
      장면 설명은 사용자가 직접 누른 버튼에 대한 대답이므로 **여전히 말합니다**. 네모(□)를 다시 두 번 눌러 음성 안내를 켭니다.
- [ ] 네모(□) B3 3초 누르고 있기: 아직 누르고 있는 동안 긴급 신고(SOS) 카운트다운이 시작됩니다(모터 3개가 1초에 한 번씩
      함께 떨리고, 음성으로 경고합니다). **아무 버튼이나 누르면 취소됩니다.** 취소되는지 확인합니다. 전체 SOS 시험은 나중에 합니다
      ([07 · 시험계획](07-시험계획.md) T9).

### G3. 안전하게 끄기

- [ ] 원(○) B1과 네모(□) B3를 **함께**(서로 1초쯤 안에) 누르고, 둘 다 **5초** 동안 누르고 있습니다.
- [ ] 헬멧이 "전원을 끕니다."라고 말하고, 준비 패턴이 거꾸로(**오른쪽 → 이마 → 왼쪽**) 나오고,
      약 3초 뒤 Pi 전원이 꺼집니다. 상태 LED가 꺼집니다.
- [ ] SOS 카운트다운이 시작되지 않았고, 마지막 안내도 다시 나오지 않았습니다.
- [ ] 다시 켭니다(전원을 뺐다가 다시 꽂습니다). 이번에는 두 버튼을 누르고 있다가 **약 2초 뒤 하나를 뗍니다**.
      아무 일도 일어나지 않습니다(끄기가 취소되고, SOS도 없습니다).

### G4. 전방 LiDAR 구간 (손이나 책으로 시험)

전방 빔은 폭이 좁습니다(2°). 2 m 거리에서 폭이 약 7 cm입니다. 목표물을 포드 정면,
머리 높이에 둡니다. 손보다 책이나 판자가 빔에 잘 맞습니다.

- [ ] 목표물이 약 **1.8 m**: 이마에 느리고 부드러운 진동(`zone3`). 음성은 없습니다.
- [ ] 목표물이 약 **1.0 m**: 빠른 진동(`zone2`)과 "앞에 장애물."
- [ ] 목표물이 약 **0.4 m**: 끊이지 않는 강한 진동(`zone1`)과 "멈추세요."
- [ ] 목표물을 약 **10 cm**까지 가져옵니다(센서가 잴 수 있는 거리보다 가깝습니다). `zone1` 진동이
      약 0.5초 동안 이어지다가 멈춥니다.
- [ ] 목표물을 멀리 치웁니다. 진동이 멈춥니다.

### G5. 책상 모서리로 내려가는 턱 시험

아래를 보는 LiDAR는 바닥까지의 거리를 학습한 값과 비교합니다. 안전을 위해 **더 먼 거리는 스스로 학습하지 않으며**,
**더 가까운** 거리가 안정적으로 유지될 때만 10초 뒤에 다시 학습합니다.

1. 도우미가 헬멧을 수평으로 **책상 윗면에서 약 1 m 위**에 들어, 아래쪽 빔이 헬멧보다
   약 80 cm 앞의 책상에 닿게 합니다. 처음에 "앞에 올라가는 턱." 경고가 나오는 것은 정상입니다.
   책상이 기본 바닥 거리보다 가깝기 때문입니다.
2. 더 가까운 책상 거리를 학습하도록 **적어도 12초 동안** 가만히 들고 있습니다.
3. 빔이 닿는 점이 책상 모서리를 넘어 바닥에 떨어지도록 헬멧을 천천히 앞으로 옮깁니다.
- [ ] **drop 패턴:** 모터 3개 모두 길게 두 번 떨리고, "앞에 내려가는 턱." 또는 "앞에 추락 위험."이라고 말합니다.
- [ ] 3초(재경고 대기 시간)를 기다린 뒤 책상 위로 되돌아오고, 높이 약 40 cm 상자를 빔 아래로 밀어 넣습니다.
      이마에 짧은 진동 세 번과 "앞에 올라가는 턱."이 나옵니다.

### G6. 카메라를 가려 고장 확인

1. 보통 밝기의 방에서 불투명한 캡이나 테이프로 카메라 렌즈를 완전히 가립니다.
- [ ] **4초** 안에 고장(FAULT) 패턴(이마에 아주 빠른 진동 세 번), "카메라가 가려졌거나 너무 어둡습니다.",
      "거리 센서는 계속 작동합니다."가 나옵니다.
- [ ] 가린 상태 그대로 1.0 m에서 G4를 반복합니다. LiDAR 경고는 계속 작동합니다.
- [ ] 고장 패턴이 10초마다 반복됩니다.
2. 렌즈를 다시 엽니다.
- [ ] "카메라 시야 복구됨."이라는 음성이 나옵니다. 고장 패턴이 멈춥니다.

### G7. 휴대폰 앱과 설정 변경 확인 안내

- [ ] 앱이 새 페어링 대화상자 없이 `OWSH-XXXX`에 연결됩니다(F에서 이미 등록했습니다).
- [ ] 앱에 상태(가동 시간, 온도, 고장)가 표시됩니다.
- [ ] 세모(△) B2 길게 누르기: 헬멧이 휴대폰에서 받은 위치를 말합니다.
- [ ] 앱 기록에 헬멧이 말한 내용이 나옵니다.
- [ ] 앱에서 헬멧 음성 안내를 끕니다. 헬멧이 "휴대폰에서 음성 안내를 껐습니다. 위험 경고는 계속 말합니다."라고 말합니다.
      다시 켭니다.
- [ ] 앱에서 낙차 감지 민감도를 낮춤으로 바꿉니다: "휴대폰에서 낙차 감지 민감도를 낮춤으로 바꿨습니다." 다시 보통으로 되돌립니다.
- [ ] 음량을 20 %로 바꿉니다: "휴대폰에서 음량을 20퍼센트로 바꿨습니다." 다시 되돌립니다.

### G8. 전원과 온도

- [ ] 평소 쓰는 보조배터리로 10분 동안 사용하는 사이에 "전원이 부족합니다. 곧 배터리를 충전하세요." 안내가 나오지 않습니다.
      나온다면 보조배터리나 케이블이 5 V 3 A를 공급하지 못하는 것입니다. 걷기 전에 교체하십시오.
- [ ] 선택: 경고가 작동하는지 확인합니다. 헬멧이 켜진 상태에서 1분 동안 약한 USB 전원(예: 5 V 1 A 충전기)으로
      전원을 공급하면서 세모(△) B2를 몇 번 누릅니다. 전압 부족이 약 10초 이어지면
      "전원이 부족합니다. 곧 배터리를 충전하세요."가 들리고, 앱 상태에 전압 부족이 표시되어야 합니다. 다시 제대로 된
      보조배터리로 바꿉니다.
- [ ] 뚜껑을 닫고 15분 동안 작동시킨 뒤, 실온 환경에서 앱에 표시되는 CPU 온도가 80 °C 미만이고,
      "헬멧이 과열되었습니다."라는 안내가 나오지 않았습니다.

하나라도 실패하면 밖에 나가기 전에 고치십시오. 흔한 원인은
[배선 가이드](02-배선가이드.md)의 8절 "자주 하는 실수"에 정리되어 있습니다.

## H. 보정

**실제 사용자가 헬멧을 쓴 상태에서**, 평소 걷는 자세로 보정합니다. 고개를 조금 숙이고 걷는 사람이 많은데,
그러면 센서가 보는 방향이 달라집니다.

### 설정 파일 위치

모든 임계값은 `firmware/config/default.yaml`에 있습니다. `owsh` 서비스는 이 파일로 펌웨어를 시작합니다
(`/etc/systemd/system/owsh.service` 참고). 개인 설정이 업데이트로 덮어써지지 않게 하려면, 이 파일을 복사하고(예:
`config/my.yaml`), 서비스 파일의 `--config`를 복사본으로 바꾼 다음
`sudo systemctl daemon-reload && sudo systemctl restart owsh`를 실행합니다. `setup_pi.sh`를 다시 실행하면
서비스 파일이 새로 쓰이므로, 그 뒤에는 이 단계를 반복하십시오.

### H1. 전방 LiDAR 방향

1. 사용자가 평평한 벽을 마주 보고 평소 자세로 **1.5 m** 떨어져 섭니다(이마에서 잽니다).
2. 기대 결과: `zone3` 느린 진동. 1.0 m에서 `zone2`. 0.5 m에서 `zone1`.
3. 구간이 너무 일찍 나오거나, 늦게 나오거나, 아예 나오지 않으면 빔이 위나 아래를 향하고 있을 가능성이 큽니다.
   2 m 거리에서 5° 기울면 빔이 닿는 점이 약 17 cm 움직입니다. `mount_pitch_deg`와 새들 위에 포드가 앉은 상태를 확인합니다.
4. 구간 거리는 설정값입니다(설계서 §5.1). 충분한 이유가 있을 때만 바꾸고, 그 이유를 기록하십시오.

### H2. 아래쪽 LiDAR 기울기와 높이

1. 사용자가 평소 자세로 헬멧을 쓴 상태에서, 도우미가 휴대폰 경사계를 포드의
   아래쪽 LiDAR 면에 댑니다.
2. 설계값은 **수평에서 아래로 50°**입니다. 다른 각도가 측정되면
   `dropoff.tilt_deg`를 측정값으로 설정합니다.
3. 착용했을 때 포드가 바닥에서 얼마나 높은지 재서 `dropoff.sensor_height_m`에 설정합니다
   (기본값 1.7 m). 펌웨어는 이 값에서 시작합니다. **더 먼 바닥 거리는 자동으로 학습하지 않으므로**
   (설계서 §5.2 안전 규칙), 처음 높이를 정확히 넣는 것이 중요합니다. 키가 큰 사용자라면 더욱 그렇습니다.
4. **앞을 볼 수 있는 도우미가 사용자의 팔을 잡은 상태로**, 위치를 알고 있는 연석이나 계단 맨 윗부분을 향해
   천천히 걸어갑니다. 가장자리에 닿기 전에 drop 경고가 나와야 합니다.

### H3. 낙차 감지 민감도

- 기본값: 반사 신호가 돌아오지 않는 경우(예: 아주 어둡거나 젖은 바닥)는 DROP으로 처리합니다. 낙차를 놓치는 것이
  잘못된 경고보다 더 나쁘기 때문입니다.
- 어두운 바닥에서 잘못된 drop 경고가 너무 잦다면, 휴대폰 앱에서 낙차 감지 민감도를
  `low`로 바꾸거나 설정 파일에서 `dropoff.no_return_is_drop: false`로 할 수 있습니다. 민감도를 낮추면 헬멧은 언제나
  음성으로 알려 줍니다. **바꾸기 전에 이 선택의 장단점을 사용자와 보행지도사(O&M 전문가)에게 설명하십시오.**

### H4. 카메라 시야

서비스를 멈춘 상태에서 사진을 찍습니다: `rpicam-still -o view.jpg`. 3 m 앞에 선 사람이
사진에 온전히 들어오고, 바닥이 대략 아래쪽 3분의 1을 채워야 합니다. 그렇지 않으면 포드 각도를 확인합니다.

### H5. 진동과 음성

- 패드마다 또렷하게 느껴져야 합니다. 그렇지 않으면 패드를 옮깁니다. **`haptics.max_duty`를 75 % 넘게 올리지 마십시오.**
  모터는 3 V 부품입니다.
- 음성 크기와 언어는 휴대폰 앱에서 설정합니다. 음성은 거리 소음 속에서도 또렷해야 하지만
  차 소리를 가려서는 안 됩니다.
- [05 · 사용자 가이드](05-사용자가이드.md)와 시뮬레이터로 사용자에게 진동 패턴을 알려 줍니다.

### H6. 휴대폰 앱, 긴급 전화번호, 보호자

앱에서 **나라별 긴급 전화번호**를 고릅니다(예: 한국은 119(구급·화재)나 112(경찰), 다른 나라는 112나 911 등).
보호자 전화번호를 추가하고, 시험이라는 것을 미리 알고 있는 보호자에게 SMS 보내기를 시험합니다.

### H7. 얼굴 등록(선택)

등록에 **동의한** 사람만 등록하십시오. 카메라가 사용 중이므로 먼저 서비스를 멈춘 다음, `firmware` 폴더에서
실행합니다.

```bash
sudo systemctl stop owsh
.venv/bin/python -m owsh.tools.enroll_face --name "Mina" --tag friend --camera 0
sudo systemctl start owsh
```

사용자가 경고받고 싶은 사람은 `--tag avoid`로 등록합니다. 사진과 얼굴 데이터는 헬멧 안에만
저장됩니다(설계서 §5.4). 등록된 사람을 확인하려면 `--list`를, 지우려면 `--remove "Mina"`를 붙여 실행합니다.

## I. 첫 실제 보행 전에

1. [07 · 시험계획](07-시험계획.md)의 절차를 실행합니다. 적어도 T2, T4, T5, T8, T9, T13, T14는 해야 합니다.
2. 처음 몇 번의 실외 보행은 **평소처럼 흰지팡이나 안내견과 함께** 하고, 보행지도사(O&M 전문가)나
   믿을 수 있는 앞을 볼 수 있는 동행자가 옆에서 함께 걷습니다.
3. 익숙하고 조용한 곳에서 시작합니다. 천천히 범위를 넓혀 갑니다.
4. 잘된 점과 잘 안된 점을 [현장 시험 보고서](../../.github/ISSUE_TEMPLATE/field_test_report.yml)에 기록합니다.

## 전원 끄기와 메모리 카드 관리

- **안전하게 끄기로 전원을 끕니다:** 원(○) B1과 네모(□) B3를 함께 5초 동안 누르고 있습니다. LED가 꺼질 때까지 기다린 다음
  전원을 뺍니다.
- 정상 종료 없이 전원을 끊으면 드물게 microSD 카드가 손상될 수 있습니다. 사용자에게 안전하게 끄는 방법을 알려 주십시오.
- 좋은 A2 등급 카드를 쓰고, 작동하는 카드의 **백업 이미지를 보관하십시오**(예: Raspberry Pi
  Imager나 `dd` 사용). 그러면 몇 분 안에 헬멧을 복구할 수 있습니다.
- M.2 HAT에 연결한 NVMe 드라이브가 microSD보다 튼튼합니다.
