# 09 · 번역 가이드

> 오픈 보행 안전 헬멧 프로젝트 문서 · CC BY 4.0 라이선스 · © 2026 씨엘소프트랩(CLSOFTLAB), 이일국 박사

이 헬멧은 길 한가운데에 있는 사람에게 말을 겁니다. 그래서 여기서 번역은 곧 안전 장비입니다. 말하는 데 오래
걸리거나, 잘못 알아듣기 쉽거나, 뜻이 모호한 경고는 사람을 다치게 할 수 있습니다. 이 가이드는 언어를 신중하게
추가하는 방법과, 그 언어가 **검증됨(verified)** 상태가 되는 과정을 설명합니다.

## 1. 번역할 수 있는 것

| 대상 | 파일 | 용도 |
|---|---|---|
| 헬멧 음성 메시지 | `firmware/owsh/i18n/<lang>.json` | 헬멧이 말하는 모든 내용(설계서 §7.1) |
| 휴대폰 앱 화면 | `app/i18n/<lang>.json` | 버튼, 레이블, 화면 낭독기 텍스트, 긴급 신고(SOS) 화면, 문자 메시지 내용 |
| 표지판 위험 키워드 | `firmware/config/default.yaml`의 `ocr.danger_keywords.<lang>` | 표지판에 이 단어가 있으면 OCR이 "경고 표지:"를 앞에 붙입니다(설계서 §5.5) |
| 문서 | `docs/<lang>/` | 이 문서 같은 가이드 |

`<lang>`은 언어 코드입니다. 예를 들면 `es`, `fr`, `pt`, `ar`, `hi`, `zh-CN`, `ja`, `sw`입니다.
지역 접미사는 그 차이가 안전이나 명확성에 중요할 때만 붙이세요(예: `pt-BR`, `zh-TW`).

참고 파일: [`firmware/owsh/i18n/en.json`](../../firmware/owsh/i18n/en.json),
[`firmware/owsh/i18n/ko.json`](../../firmware/owsh/i18n/ko.json), 그리고 [`app/i18n/`](../../app/i18n/)에 있는 앱 파일들.

## 2. 검증됨(verified) 규칙

설계서의 프로젝트 전체 규칙에 따릅니다.

- `en`과 `ko`는 핵심 팀이 관리합니다.
- 다른 언어도 모두 환영합니다. 다만 **해당 언어가 모국어인 시각장애인, 또는 그 언어가 모국어인
  보행지도사(O&M 전문가)**의 검토를 거친 뒤에만 **검증됨(verified)**으로 표시합니다.
- **검증되지 않은 언어도 배포합니다.** 이때는 처음 켤 때 그 언어가 아직 검증되지 않았다는 안내가 나옵니다.

왜 이런 규칙을 둘까요? 앞을 보는 번역자는 글로 읽으면 자연스럽지만, 차가 오가는 길에서 골전도 헤드셋으로
한 번 들었을 때는 알아듣기 어려운 문구를 쓰기 쉽습니다. 매일 음성에 의지하는 사람과, 혼자 다니는 법을
가르치는 사람은 그런 문제를 잘 잡아냅니다.

검증은 이렇게 진행합니다.

1. 번역자가 언어 파일을 담아 풀 리퀘스트를 엽니다.
2. 규칙에 맞는 검토자가 [7장](#7-검증용-검토-체크리스트)의 체크리스트로 **음성 문구**를 검토합니다. 가능하면
   헬멧이나 시뮬레이터로 직접 들어 봅니다.
3. 검토자는 풀 리퀘스트에 댓글을 남깁니다. 어떤 자격인지(해당 언어가 모국어인 시각장애인 또는 보행지도사),
   문구를 직접 들어 보았는지, 무엇을 고쳤는지를 적습니다. 공개적으로는 익명으로 남아도 되며, 관리자가 따로
   비공개로 확인할 수 있습니다.
4. 관리자가 `firmware/owsh/i18n/__init__.py`의 `VERIFIED_LANGS`에 언어 코드를 추가하고(그러면 첫 부팅 안내가
   나오지 않습니다), [언어별 상태 표](#9-언어별-상태)를 갱신합니다.
5. 나중에 안전 문구(P0–P2 수준)를 하나라도 바꾸면, 그 문구는 다시 검토를 받아야 합니다.

## 3. 헬멧 음성 언어 추가하기

1. **이슈를 여세요.** [번역 양식](../../.github/ISSUE_TEMPLATE/translation.yml)으로 이슈를 열어, 다른 사람들이
   작업 중이라는 것을 알 수 있게 합니다.
2. `firmware/owsh/i18n/en.json`을 `firmware/owsh/i18n/<lang>.json`으로 **복사합니다**.
3. **값만 번역합니다.** 키는 모두 그대로 둡니다.
4. **`{placeholders}`는 바꾸지 않습니다.** 예를 들어 `{name}`, `{what}`, `{count}`입니다. 문장 안에서 위치를 옮기는 것은 괜찮습니다.
5. **키를 하나도 빼지 않습니다.** 펌웨어 테스트는 각 언어 파일이 `en.json`과 정확히 같은 키와 `{placeholders}`를
   가지고 있는지 검사합니다. 아직 번역하지 못한 문구가 있으면 값에 영어 문장을 그대로 두고 풀 리퀘스트에 목록으로
   적어 주세요. (실행 중에는 빠진 문구를 영어로 대신 말하므로 경고가 조용해지는 일은 없지만, 테스트는 여전히
   실패합니다.)
6. **음성 엔진을 확인합니다.** Pi의 기본 엔진은 `espeak-ng`입니다. 여러분의 언어가 있는지 확인하세요.
   ```bash
   espeak-ng --voices | grep -i <lang>
   espeak-ng -v <lang> "your translated warning"
   ```
   `espeak-ng`의 발음이 나쁘면 풀 리퀘스트에 적어 주세요. `piper` 음성이 더 나을 수 있습니다(설계서 §7.1).
7. **표지판 읽기용 위험 키워드를 추가합니다.** `firmware/config/default.yaml`의 `ocr.danger_keywords` 아래에
   `<lang>:` 목록을 새로 만들어 여러분 언어의 단어를 넣습니다(예: "위험", "주의", "미끄럼 주의", "공사"에 해당하는 단어).
   새로운 문자 체계라면 그 문자용 인식 모델(`ocr.rec_model_path`)과 `ocr.languages` 항목도 필요할 수 있습니다.
8. PC에서 여러분의 언어를 선택하고 **시뮬레이터로 들어 봅니다.**
   ```bash
   python -m owsh --sim --lang <lang>
   ```
   가상 버튼을 누르고 라이다 슬라이더를 움직여 모든 경고가 한 번씩 나오게 합니다.
9. **JSON을 검사하고** 테스트를 실행합니다(테스트가 키와 플레이스홀더가 일치하는지 검사합니다).
   ```bash
   python -m json.tool firmware/owsh/i18n/<lang>.json > /dev/null
   cd firmware && python -m pytest -q
   ```
10. **풀 리퀘스트를 엽니다.** 검증됨(verified) 규칙에 맞는 검토자를 구할 수 있는지도 함께 적어 주세요.

형식 규칙:

- UTF-8, 바이트 순서 표시(BOM) 없음, 공백 2칸 들여쓰기, 끝에 붙는 쉼표 없음.
- 변경 내용을 검토하기 쉽도록 `en.json`과 같은 키 순서를 유지합니다.
- 숫자와 단위: 숫자는 펌웨어가 넣습니다. 단위는 소리 내어 읽는 방식으로 씁니다("m"가 아니라 "미터").
  기본은 미터법이며, 음성은 야드파운드법으로도 바꿀 수 있습니다.
- 복수형: 물체 이름은 `.one`과 `.many` 두 키로 나뉩니다(예: `class.person.one`, `{count}`가 들어간
  `class.person.many`). 여러분 언어에 형태가 더 필요하면 어떤 숫자에도 맞는 표현을 고르고 풀 리퀘스트에 적어 주세요.

`en.json`의 실제 항목 예시:

```json
{
  "obstacle.stop": "Stop.",
  "obstacle.ahead": "Obstacle ahead.",
  "approach.p2.right": "{what} approaching from the right.",
  "class.person.many": "{count} people",
  "face.friend.left": "{name} is ahead on the left."
}
```

## 4. 앱 언어 추가하기

1. `app/i18n/en.json`을 `app/i18n/<lang>.json`으로 복사합니다.
2. 값을 번역합니다. 키와 `{placeholder}`는 모두 그대로 둡니다(앱 테스트도 이것을 검사합니다).
3. `app/js/i18n.js`의 `SUPPORTED_LANGUAGES`에 언어 코드를 추가합니다.
4. **화면 낭독기 텍스트는 눈에 보이는 텍스트만큼 중요합니다.** 버튼과 상태 레이블은 그것만 따로 읽어도 뜻이
   통해야 합니다.
5. **긴급 신고(SOS) 화면과 문자 메시지 내용은 안전 텍스트입니다.** 문자는 보호자에게 가고, 긴급 구조 기관이 읽을
   수도 있습니다. 누가 도움이 필요한지, 긴급 상황이라는 것, 지도 링크를 짧고 분명하게 담으세요.
6. **긴급 전화번호는 절대 문구 안에 번역해 넣지 않습니다.** 번호는 나라별 설정입니다. 문자열에 "112에 전화하세요"나
   "911에 전화하세요" 같은 내용을 쓰지 마세요.
7. 오른쪽에서 왼쪽으로 쓰는 언어(예: `ar`)는 화면 배치가 좌우 반전되는지, 화면 낭독기가 올바른 순서로 읽는지
   확인하세요.
8. Node 22로 앱 테스트를 실행한 다음(`cd app && node --test tests/*.test.mjs`), 휴대폰에서 화면 낭독기(TalkBack
   또는 VoiceOver)를 켜고 앱을 열어 모든 화면을 하나씩 확인합니다.

## 5. 좋은 안전 문구 쓰기

우선순위 P0–P2 메시지(설계서 §6.1)가 가장 중요합니다. 이 메시지를 쓸 때는 다음을 지켜 주세요.

- **짧게.** 경고는 위험이 닥치기 전에 끝나야 합니다. 한 단어에서 세 단어를 목표로 하세요. "Stop"(멈추세요)은
  여러분 언어에서 가능한 한 짧아야 합니다.
- 행동을 요구하는 문구라면 **행동을 먼저** 말하세요. 직접적인 명령형을 씁니다. 음절이 늘어나거나 선택 사항처럼
  들리는 공손한 표현은 피하세요. 단, 여러분의 문화에서 직접적인 표현이 무례하게 들린다면 예외입니다.
- **잘못 알아듣기 어렵게.** "Step up"과 "Step down"은 짧은 음절 하나 차이가 아니라 분명히 다르게 들려야 합니다.
  너무 비슷하다면 표현을 바꾸세요(예: "Step down"과 "Kerb up").
- **왼쪽과 오른쪽**은 언제나 착용자 기준입니다.
- **한 단어에는 한 가지 뜻만.** 같은 대상은 어디서나 같은 단어로 부르세요. 동의어를 섞어 쓰지 마세요.
- 경고에는 **농담, 관용구, 지역 방언이나 속어를 쓰지 않습니다.**
- **소음 속에서 들어 보세요.** 거리 소음을 틀어 놓고, 오픈형 헤드셋으로, 평소 음량에서 문구를 들어 봅니다.
- **메시지 id의 뜻을 지키세요.** 두 메시지를 하나로 합치거나, 메시지가 경고하는 내용을 바꾸지 마세요.

## 6. 안전 용어집

아래 용어는 헬멧과 앱 모두에서 일관되게 번역해 주세요. 한국어 열은 핵심 팀이 쓰는 기준 번역입니다.

| 용어(영어) | 뜻과 참고 사항 | 한국어 기준 번역 |
|---|---|---|
| Stop | 지금 바로 걸음을 멈추라는 뜻. 가장 짧은 형태로. Z1 장애물일 때 말합니다. | 멈추세요 |
| Obstacle ahead | 앞쪽 0.6–1.2 m, 머리 높이에 무언가 있음. | 앞에 장애물 |
| Step down ahead | 내려가는 턱, 연석, 계단. | 앞에 내려가는 턱 |
| Drop ahead | 더 깊은 낙차: 승강장 끝, 계단, 구멍. | 앞에 추락 위험 |
| Step up ahead | 올라가는 턱이나 낮은 장애물. "step down"과 분명히 다르게 들려야 합니다. | 앞에 올라가는 턱 |
| approaching | 착용자 쪽으로 다가옴. 물체와 방향과 함께 씁니다. | 접근 |
| left / right | 착용자 기준. | 왼쪽 / 오른쪽 |
| ahead | 착용자 앞쪽. | 앞 |
| person, bicycle, car, motorcycle, bus, truck, dog | 다가올 수 있는 검출 클래스. 일상적인 단어를 쓰세요. | 사람, 자전거, 자동차, 오토바이, 버스, 트럭, 개 |
| Warning sign: | 위험 단어가 있는 표지판을 읽기 전에 붙이는 머리말. | 경고 표지: |
| Emergency alert | 긴급 신고(SOS) 기능. 일반 알림과 헷갈리면 안 됩니다. | 긴급 신고 |
| Emergency alert in 10 seconds. Press any button to cancel. | 긴급 신고(SOS) 카운트다운. | 10초 뒤 긴급 신고를 보냅니다. 취소하려면 아무 버튼이나 누르세요. |
| Sending emergency alert to the phone. | 헬멧이 아직 휴대폰에 전달하려고 시도하는 중. "보냈다"처럼 들리면 안 됩니다. | 휴대폰으로 긴급 신고를 보내는 중입니다. |
| Emergency alert sent | 휴대폰이 긴급 신고를 받았다고 확인한 뒤에만 말합니다. | 긴급 신고를 보냈습니다 |
| cancel / cancelled | 긴급 신고(SOS) 카운트다운을 멈춤. | 취소 / 긴급 신고를 취소했습니다 |
| Phone not connected | 헬멧이 휴대폰과 연결되지 않음. | 휴대폰이 연결되지 않았습니다 |
| fault | 헬멧의 한 부분이 작동을 멈춤. 사소하게 들린다면 "문제"나 "이상"처럼 약하게 옮기지 마세요. | 고장 |
| Camera is covered or too dark | 카메라 가림 고장(FAULT). | 카메라가 가려졌거나 너무 어둡습니다 |
| Distance sensors still active | 라이다 경고는 계속 작동함. | 거리 센서는 계속 작동합니다 |
| recovered | 고장 났던 부분이 다시 작동함. | 복구됨 |
| muted / unmuted | 낮은 우선순위 음성 끄기 / 켜기. 경고와 버튼을 눌렀을 때의 응답은 계속 말합니다. | 음성 안내를 끕니다 / 음성 안내를 켭니다 |
| Shutting down. | 안전하게 끄기 시작(B1 + B3를 5 s 누름). | 전원을 끕니다. |
| Power is low. Charge the battery soon. | 전압 부족 경고. 헬멧이 곧 멈출 수 있음. | 전원이 부족합니다. 곧 배터리를 충전하세요. |

## 7. 검증용 검토 체크리스트

검토자(해당 언어가 모국어인 시각장애인 또는 보행지도사)는 P0–P2 문구 하나하나를 다음 기준으로 확인합니다.

- [ ] 글로 읽기만 하지 않고, 헬멧이나 시뮬레이터로 직접 들어 보았다.
- [ ] 거리 소음이 깔린 상태에서 한 번에 알아들었다.
- [ ] 걸으면서 바로 행동할 수 있을 만큼 짧다.
- [ ] 무엇을 해야 하는지, 또는 무엇이 있는지 모호하지 않게 알려 준다.
- [ ] "Step up"과 "step down"(또는 그에 해당하는 표현)을 헷갈릴 수 없다.
- [ ] 왼쪽과 오른쪽이 내 기준이다.
- [ ] 같은 대상을 모든 메시지에서 같은 말로 부른다.
- [ ] 말투가 알맞다: 필요한 곳에서는 급박하고, 정보 메시지에서는 불안감을 주지 않는다.
- [ ] 음성 엔진이 올바르게 발음한다.
- [ ] 처음 켤 때 나오는 메시지가 헬멧은 보조 도구이며 흰지팡이나 안내견을 대신하지 않는다고 분명히 말한다.

앱:

- [ ] 모든 화면이 화면 낭독기로 작동한다.
- [ ] 긴급 신고(SOS) 화면과 문자 메시지 내용을 처음 보는 사람도 분명히 이해할 수 있다.

  문서부터 시작하세요.

- 숫자, 핀, 명령어, 파일 이름은 모두 바꾸지 않습니다.
- 단어를 하나하나 옮기지 말고, 읽는 사람에게 자연스러운 글로 쓰세요.
- [`docs/README.md`](../README.md)에 여러분의 언어를 추가해 주세요.
