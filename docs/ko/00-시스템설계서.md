### 프로젝트 공통 규칙
- 코드, 설계서, 이슈의 기본 언어는 **영어**입니다. 사용자용 가이드는 모두 **한국어**로도 제공합니다.
- 음성/화면 문구: `en`과 `ko`는 핵심 팀이 관리합니다. 다른 언어
  (`es`, `fr`, `pt`, `ar`, `hi`, `zh-CN`, `ja`, `sw`, …)도 환영하지만, 해당 언어가 모국어인 시각장애인이나
  보행지도사(O&M 전문가)의 검토를 거쳐야 **"검증됨(verified)"**으로 표시합니다. 안전 문구는 오해의 여지가
  없어야 하기 때문입니다. 검증되지 않은 언어는 첫 부팅 때 안내 문구와 함께 제공됩니다.
- 긴급 전화번호는 국가별 설정값이며, 특정 국가 번호로 코드에 고정하지 않습니다.
- 단위: 기본은 미터법이며, 음성 안내는 야드파운드법도 선택할 수 있습니다.

## 1. 목표와 설계 원칙

**목표:** 누구나 살 수 있고 출력할 수 있는 부품으로, 세계 어디서든 시각장애인과 저시력인이
비장애인처럼 자유롭고 안전하게 걸을 수 있게 합니다.

**안경이 아니라 헬멧인 이유:** 충돌이나 넘어짐이 결국 일어나더라도 헬멧은 머리를 보호합니다.
따라서 헬멧의 보호 기능은 **절대 양보할 수 없습니다**:

| # | 원칙 | 결과 |
|---|---|---|
| P1 | **충격 보호 성능을 절대 떨어뜨리지 않는다** | 인증받은 자전거/멀티스포츠 헬멧(EN 1078, CPSC 1203, AS/NZS 2063, KC 또는 동등 인증)을 사용합니다. 헬멧 외피(셸)를 3D 프린팅하지 않습니다. EPS 라이너나 외피에 구멍을 뚫거나, 자르거나, 접착하거나, 녹이지 않습니다. |
| P2 | **충격 시 떨어져 나가는 낮은 부착물** | 외부 모듈은 통풍구로 통과시킨 벨크로 스트랩 그리고/또는 떼어낼 수 있는 접착 패드로 붙여, 충격을 받으면 떨어져 나가게 합니다. 외피 위 최대 높이: **전방 포드 35 mm, 메인 케이스 40 mm**(Active Cooler를 단 Pi 5는 더 낮게 들어가지 않음), **그 밖의 모든 모듈 30 mm**. 바닥면은 외피 곡면에 맞춘 곡면이며 두께가 고른 3 mm TPU 새들 위에 놓습니다 — 받침 기둥이나 5 mm를 넘는 틈은 없어야 합니다. 바깥 모서리는 모두 둥글게(필렛 ≥ 3 mm), 날카로운 끝이 없어야 합니다. |
| P3 | **보조할 뿐, 대체하지 않는다** | 헬멧은 흰지팡이나 안내견을 보완합니다. 문서와 첫 부팅 음성 안내에서 이를 분명히 알립니다. |
| P4 | **고장 났을 때 침묵이 "안전"을 뜻해서는 안 된다** | 모든 하위 시스템을 감시합니다. 고장이 나면 구별되는 FAULT 패턴(§5.7, §6.2)을 냅니다. |
| P5 | **AI와 독립적인 안전 경로** | 라이다 즉시 경고 경로(reflex path, §5.1)는 카메라나 신경망 없이도 동작합니다. |
| P6 | **오프라인 우선** | 모든 위험 경고는 헬멧에서 계산합니다. 휴대폰/인터넷은 위치, 긴급 신고(SOS), 선택 기능에만 씁니다. |
| P7 | **전 세계 어디서나 제작 가능** | 전 세계에서 구할 수 있는 부품만 사용합니다(AliExpress, DigiKey, Mouser, Pimoroni, 각국 Raspberry Pi 리셀러). 참조 빌드는 납땜이 없습니다(듀폰/JST 커넥터). 부품은 220×220×250 mm FDM 프린터로 출력할 수 있습니다. |
| P8 | **기본부터 접근성** | 모양이 서로 다른 촉각 버튼, 사용자 언어의 음성 안내(ko, en 우선), 스크린 리더 친화적인 휴대폰 앱. |
| P9 | **허용적 라이선스** | 기본 빌드에는 Apache-2.0 / MIT / BSD 모델과 라이브러리만 사용합니다(AGPL 제외). |

## 3. 시스템 구조

```
                 ┌──────────────────────────── HELMET ────────────────────────────┐
                 │                                                                │
 Camera Module 3 ─┤► vision thread: capture → dehaze → detector → tracker → TTC ──┐│
 Wide (CSI)       │                          └► faces (on demand / low rate)      ││
                  │                          └► OCR (button-triggered)            ││
 TF-Luna FWD ─I2C─┤► reflex thread 50 Hz: head-height obstacle zones ────────────┤│
 TF-Luna DOWN ─I2C┤► reflex thread 50 Hz: drop-off / step detector ──────────────┤│
 MPU-6050 ────I2C─┤► imu thread 100 Hz: fall detection ──────────────────────────┤│
 3 buttons ──GPIO─┤► input thread: short / long / double press ──────────────────┤│
                  │                                                              ▼│
                  │                              EVENT BUS ──► hazard arbiter ─────┤
                  │                                               │                │
                  │           ┌───────────────────────────────────┼──────────┐     │
                  │           ▼                                   ▼          ▼     │
                  │   haptics (ULN2003 → 3 ERM)          audio (USB headset)  BLE link
                  │                                                              │ │
                  │  watchdog: heartbeats of every thread → FAULT events         │ │
                  └──────────────────────────────────────────────────────────────┼─┘
                                                                                 │ Nordic UART Service
                                                                   PHONE APP (PWA, Web Bluetooth)
                                                                   location · SOS · settings · log
```

그림 용어: vision thread = 영상 스레드(촬영 → 안개 제거 → 검출 → 추적 → TTC), faces = 얼굴 인식(요청 시 / 낮은 주기),
OCR = 글자 읽기(버튼 실행), reflex thread = 즉시 경고 스레드(머리 높이 장애물 구간 / 단차·계단 검출),
imu thread = IMU 스레드(넘어짐 감지), input thread = 입력 스레드(짧게 / 길게 / 두 번 누르기),
EVENT BUS = 이벤트 버스, hazard arbiter = 위험 판정기, haptics = 진동, audio = 음성,
watchdog = 감시기(모든 스레드의 heartbeat → FAULT 이벤트), PHONE APP = 휴대폰 앱(위치 · SOS · 설정 · 기록).

실행 환경: Raspberry Pi OS Bookworm 64비트, Python ≥ 3.11, 단일 프로세스, 하위 시스템마다 스레드 하나,
스레드 안전 이벤트 버스. 자동 재시작되는 systemd 서비스로 실행합니다.

### 4.2 Raspberry Pi 5 핀 배치 (BCM 번호) — **기준값**

| 기능 | BCM GPIO | 헤더 핀 | 방향 | 비고 |
|---|---|---|---|---|
| I2C1 SDA | GPIO2 | 3 | bus | TF-Luna FWD 0x10, TF-Luna DOWN 0x11, MPU-6050 0x68 |
| I2C1 SCL | GPIO3 | 5 | bus | 400 kHz (`dtparam=i2c_arm=on,i2c_arm_baudrate=400000`) |

| 진동 CENTER | GPIO27 | 13 | out | → ULN2003 IN2 → M2 |

| 버튼 B1 (원) | GPIO5 | 29 | in, pull-up | active-low |

- **TF-Luna I2C 모드:** 커넥터 5번 핀(configuration)을 GND에 연결하면 I2C가 선택됩니다. TF-Luna의 신호는
  3.3 V와 호환되며, 전원은 5 V로 공급합니다. 하방 라이다의 주소는 한 번만 0x10에서 0x11로 바꿉니다:
  `python -m owsh.tools.tfluna_addr --from 0x10 --to 0x11`.
- **ULN2003에 연결한 ERM 모터:** 모터 +는 ULN2003 보드의 "+"(5 V)에, 모터 −는 OUT1..OUT3에 연결합니다.
  ULN2003 달링턴 전압 강하(약 1 V) 때문에 약 4 V가 걸리므로, 펌웨어는 PWM 듀티를 75 %로 제한해
  (`haptics.max_duty`) 3 V 모터에 과전압이 걸리지 않게 합니다.
- **카메라:** Pi 5의 CAM/DISP 0 커넥터.
- **오디오:** USB 오디오 어댑터는 USB 2.0 포트 아무 곳에나 꽂습니다(BLE 주변 2.4 GHz 잡음을 줄이기 위해 USB 3 포트는 비워 둡니다).
- **전력 예산:** Pi 5 부하 시 약 6.5 W, 주변 장치 약 1.5 W → 약 8 W. 3 A 전원에서는 USB 주변 장치 전류가
  600 mA로 제한되지만 충분합니다. 10 000 mAh ≈ 3.5 시간, 20 000 mAh ≈ 7 시간(보수적 추정).

## 5. 감지와 위험 판단 로직

### 5.1 즉시 경고 경로 — 전방 라이다 (머리 높이 장애물)

머리 높이 장애물(나뭇가지, 트럭 사이드미러, 간판, 열린 창문)은 흰지팡이로 알 수 없는 위험입니다.
50 Hz로 반복하며, 최근 3개 측정값의 중앙값을 씁니다. 유효하지 않은 측정값(신호 세기 < 100 또는 거리 = 0)은
"반사 없음"으로 봅니다.

| 구간 | 거리 | 진동 (CENTER 모터) | 음성 |
|---|---|---|---|
| Z3 알림 | 2.0 m ≥ d > 1.2 m | 2 Hz 짧은 진동, 40 % | 없음 |
| Z2 경고 | 1.2 m ≥ d > 0.6 m | 5 Hz 진동, 70 % | "Obstacle ahead"(앞에 장애물) 5초에 한 번 |
| Z1 임박 | d ≤ 0.6 m | 연속 100 % | "Stop"(멈추세요) (다른 음성을 끊고 우선) |

구간 사이 히스테리시스 0.1 m. 구간 경계값은 설정값입니다.
근거리 신호 끊김: TF-Luna는 0.2 m보다 가까우면 아무 값도 돌려주지 않습니다. 측정값이 Z1에 있다가 반사 없음으로 바뀌면
조용해지는 대신 Z1을 **0.5초 동안 유지**합니다.

### 5.2 즉시 경고 경로 — 하방 라이다 (낭떠러지와 단차)

기울기 θ = 수평에서 아래로 50°(설정 `dropoff.tilt_deg`). 평지를 걷는 동안 예상 거리 d₀는
분산이 낮은 측정값 3초 분량의 이동 중앙값으로 학습합니다(자동 보정, 1.2–3.5 m로 제한). **안전 규칙:** 더 긴 거리가
측정되는 동안 d₀를 자동으로 늘리지 않습니다(승강장 끝에 가만히 서 있을 때 선로 바닥을 "지면"으로 배우면 안 되기 때문).
더 짧은 거리가 안정적으로 유지되면 10초 뒤에 다시 학습합니다(예: 앉았을 때, 경사로).

- **DROP (내려가는 계단, 연석, 승강장 끝):** d > d₀ × 1.30 **또는** 반사 없음이 120 ms 이상 지속
  → P1 IMMINENT, 모든 모터가 긴 진동 2회, 음성 "Step down ahead"(앞에 내려가는 턱) / "Drop ahead"(앞에 추락 위험).
- **STEP UP (올라가는 단차 / 낮은 장애물):** d < d₀ × 0.70이 120 ms 이상 지속 → P2 WARNING, 가운데 모터
  짧은 진동 3회, 음성 "Step up ahead"(앞에 올라가는 턱).
- 종류별 재알림 대기 3초. 아주 어둡거나 젖은 바닥에서 반사가 없으면 DROP으로 보고합니다. 낭떠러지를 놓치는 것이
  오경보보다 더 나쁘기 때문입니다. 사용자는 민감도를 낮출 수 있습니다(`dropoff.no_return_is_drop: false`).

### 5.3 영상 경로

- 1280 × 720으로 촬영 → 검출기 크기로 축소. Pi 5에서 목표 ≥ 8 FPS.
- 전처리: 안개/비/저조도에 대비한 휘도 CLAHE 선택 적용(`vision.dehaze: auto|on|off`).
- 검출기: **NanoDet-Plus-m 416** (OpenCV Zoo `object_detection_nanodet_2022nov.onnx`,
  Apache-2.0), `cv2.dnn`으로 실행. 호환되는 ONNX 모델이면 무엇이든 설정할 수 있습니다.
- 관심 클래스(COCO): person, bicycle, car, motorcycle, bus, truck, dog, horse,
  bench, fire hydrant, stop sign, parking meter, traffic light, chair, potted plant, suitcase.
  "움직이는 것(movers)" = person, bicycle, car, motorcycle, bus, truck, dog, horse.
- 추적기: IoU 탐욕(greedy) 추적기, 검출이 없어도 트랙을 0.7초 유지.
- 방향: 카메라 수평 화각(Camera Module 3 Wide: 102°)을 이용해 경계 상자 중심에서 수평 각도를 구합니다.
  LEFT < −15° ≤ CENTER ≤ +15° < RIGHT.
- 충돌 예상 시간(TTC): TTC = Δt / (s − 1), s = 0.4초 이상 구간의 경계 상자 높이 비율(평활화).
- 경고:
  - **APPROACH P1:** TTC < 1.5 s이고 경계 상자 높이가 화면의 20 %를 넘는 움직이는 것.
  - **APPROACH P2:** TTC < 3.0 s(차량: < 4.0 s)이고 경계 상자 높이가 화면의 10 %를 넘는 움직이는 것.
  - 조건이 **처리된 프레임 2장 연속**으로 성립해야 합니다(경계 상자 떨림 억제).
- 같은 단계는 트랙별 재알림 대기 5초; 더 높은 단계로 올라가면 대기를 무시합니다.
- 검출기 입력 색상 순서는 설정할 수 있습니다(`color_order: rgb|bgr`, 기본값은 OpenCV Zoo 데모와 같은 rgb).
- **장면 설명 (버튼):** 가까운 순서(경계 상자 높이)로 최대 5개 물체를 클래스와 방향별로 묶어 말합니다:
  "2 people ahead, bicycle on the right"(앞에 사람 2명, 오른쪽에 자전거).

### 5.4 얼굴

- YuNet 2023mar 검출기 + SFace 2021dec 인식기 (OpenCV Zoo, MIT / Apache-2.0).
- 사람이 검출되었을 때 가장 최근 프레임에서 ≤ 2 Hz로 실행합니다.
- 등록 데이터베이스: `data/faces/<name>/{*.jpg}` + `data/faces/index.json`, `tag: friend|avoid`.
  등록 명령: `python -m owsh.tools.enroll_face --name "Mina" --tag friend --camera 0` (또는 이미지로 등록).
- 일치 판단: 코사인 유사도 ≥ 0.363 (SFace 권장 임계값). 마스크 대응: YuNet 신뢰도 ≥ 0.6이면 얼굴 일부만
  보여도 받아들입니다. 더 낮은 유사도 임계값도 설정할 수 있습니다.
- friend → P3 INFO "Mina is ahead on the left"(왼쪽 앞에 민아 님), 해당 쪽 짧은 진동 2회,
  사람별 재알림 대기 60초.
- avoid → 음성과 함께 P2 WARNING, 재알림 대기 60초.
- 개인정보: 얼굴 특징값(embedding)과 사진은 헬멧 밖으로 나가지 않습니다. BLE로는 이름만 보냅니다.

### 5.5 OCR (버튼 실행)

- 설치되어 있으면 `rapidocr_onnxruntime`(Apache-2.0) 백엔드를 사용하며, 언어는 설정에서 정합니다. 설치되어 있지 않으면
  음성 "Text reading is not installed"(문자 읽기 기능이 설치되어 있지 않습니다).
- 새로 찍은 프레임의 가운데 70 % 영역을 읽고, 줄을 위에서 아래 순서로 정리해 최대 200자까지 말합니다.
  B1을 길게 누르면 마지막으로 말한 메시지를 반복합니다.
- 위험 키워드(언어별 설정 목록, 예: "위험", "공사", "DANGER", "CAUTION", "WET FLOOR")가 들어간 표지판은
  앞에 "Warning sign:"(경고 표지:)을 붙여 읽습니다.

### 5.6 넘어짐 감지 (IMU)

- 자유낙하 |a| < 0.35 g가 80 ms 이상 → 1초 안에 충격 |a| > 2.5 g → 이후 2초간 움직임 적음
  (|a|가 1 ± 0.15 g 이내) → FALL → SOS 카운트다운(§7.3).

### 5.7 감시기 (watchdog)

각 스레드는 heartbeat를 보냅니다. 시간 제한: 카메라 프레임 2 s, 라이다 0.5 s, IMU 1 s,
오디오 백엔드 초기화 실패는 즉시.

**카메라 가림 / 보이지 않는 카메라:** 프레임은 계속 들어오지만 렌즈가 가려졌거나(진흙, 빗물막,
스티커, 모자) 완전히 어두운 경우입니다. 평균 휘도 < 12 (0–255) **이고** 휘도 표준편차 < 6이
3초 이상 지속되거나, **또는** 픽셀의 97 % 이상이 12보다 어두운 상태가 3초 이상 지속되면(작은 아이콘이 있는 개인정보
보호 셔터 화면) FAULT `camera_blocked`를 냅니다(음성: "Camera is covered or too dark"(카메라가 가려졌거나 너무 어둡습니다.)).
라플라시안 분산(선명도)이 5초 이상 < 5로 유지될 때(렌즈 번짐)도 같은 FAULT를 냅니다. 라이다 즉시 경고 경로는
계속 동작하며 음성으로 알립니다("Distance sensors still active"(거리 센서는 계속 작동합니다.)).

**전원과 온도 (Pi):** 펌웨어 `get_throttled` 플래그를 5초마다 읽습니다. 저전압(bit 0)이 10초 이상 계속되면
→ P2 "Power is low. Charge the battery soon."(전원이 부족합니다. 곧 배터리를 충전하세요.) (최대 5분에 한 번).
CPU ≥ 80 °C → P2 "Helmet is overheating."(헬멧이 과열되었습니다.) (최대 5분에 한 번, 75 °C 아래로 내려가면 다시 활성화).
고장 → FAULT 이벤트(구성요소 id). **안전과 관련된 구성요소**(카메라, 라이다, 진동, IMU)의 FAULT는 지속되는 동안
10초마다 반복합니다(P0). 안전과 무관한 구성요소(얼굴, OCR, BLE, 설정)는 P2로 한 번만 알립니다.
복구 → 음성 "<component> recovered"(<구성요소> 복구됨.).

## 6. 진동 언어 (모터 L = 왼쪽 관자놀이, C = 이마, R = 오른쪽 관자놀이)

### 6.1 우선순위

| 단계 | 이름 | 예 | 우선하는 대상 |
|---|---|---|---|
| P0 | CRITICAL (위급) | SOS 카운트다운, 시스템 FAULT | 전부 |
| P1 | IMMINENT (임박) | Z1 장애물, DROP, APPROACH P1 | P2–P4 |
| P2 | WARNING (경고) | Z2 장애물, STEP UP, APPROACH P2, 기피 대상 | P3–P4 |
| P3 | INFO (정보) | Z3 알림, 지인 얼굴, OCR 결과, 장면 설명 | P4 |
| P4 | STATUS (상태) | 준비 완료, 버튼 확인 진동, 음소거 전환 | — |

진동 믹서는 활성화된 모든 패턴을 모터별로 계산하고, 10 ms 틱마다 모터별 **최댓값** 세기를 사용합니다
(연속되는 즉시 경고 패턴과 한 번만 울리는 패턴이 함께 존재할 수 있음). 음성은 엄격한 선점 방식입니다(§7.1).

### 6.2 패턴 표 (기준값)

| 패턴 id | 모터 | 타이밍 | 의미 |
|---|---|---|---|
| `tick` | C | 40 ms @ 60 % | 버튼 입력 확인 / "작동 중" |
| `zone3` | C | 반복: 60 ms 켬 / 440 ms 끔 @ 40 % | 장애물 1.2–2.0 m |
| `zone2` | C | 반복: 80 ms 켬 / 120 ms 끔 @ 70 % | 장애물 0.6–1.2 m |
| `zone1` | C | 연속 @ 100 % | 장애물 ≤ 0.6 m |
| `drop` | L+C+R | 2 × (400 ms 켬 / 150 ms 끔) @ 100 % | 낭떠러지 / 내려가는 계단 |
| `step_up` | C | 3 × (100 ms 켬 / 100 ms 끔) @ 80 % | 올라가는 단차 / 낮은 장애물 |
| `approach_left` / `approach_right` / `approach_center` | L / R / C | 3 × (150 ms 켬 / 80 ms 끔) @ 100 % (P1) 또는 70 % (P2) | 그쪽에서 움직이는 물체가 다가옴 |
| `person_friend_<side>` | 해당 쪽 | 2 × (80 ms 켬 / 120 ms 끔) @ 60 % | 등록된 지인 |
| `person_avoid_<side>` | 해당 쪽 | 4 × (60 ms 켬 / 60 ms 끔) @ 90 % | 등록된 기피 대상 |
| `turn_left` / `turn_right` | L / R | 250 ms 켬 / 750 ms 끔, 활성 동안 반복 @ 70 % | 방향 안내(내비게이션, 로드맵) |
| `count_n` | C | n × (120 ms 켬 / 280 ms 끔) @ 70 %, n ≤ 10 | 숫자(예: 층수) [0044] |
| `sos_countdown` | L+C+R | 1 Hz 200 ms @ 100 %, 10초간 | SOS를 보낼 예정 |
| `fault` | C | 3 × (50 ms 켬 / 50 ms 끔) @ 100 %, 10초마다 | 하위 시스템 고장 — 침묵을 믿지 말 것 |
| `ready` | L → C → R | 각 100 ms, 순서대로 @ 60 % | 부팅 완료 |

## 7. 음성, 버튼, SOS

### 7.1 음성

- 백엔드 순서: `piper` CLI(설정한 경우, 자연스러운 음성), `espeak-ng`(Pi 기본, ko/en 지원),
  `pyttsx3`(데스크톱 개발용). 고정 문구는 미리 만든 WAV 파일을 `data/cache/tts/`에 캐시합니다.
- 대기열: 우선순위가 더 높은 메시지는 현재 메시지를 끊고, 같거나 낮은 메시지는 기다립니다.
  대기 중인 P1/P2 메시지가 2초보다 오래되면 버립니다. 대기열은 최대 3개입니다.
- 음소거(B3 두 번 누르기)는 P3–P4 음성만 끕니다. P0–P2는 항상 말합니다. **버튼으로 요청한 것에 대한 대답
  (글자 읽기, 장면 설명, 상태 안내, 여기가 어디인지, 누가 있는지)은 음소거 중에도 말합니다.**
- 모든 문구는 메시지 id를 키로 하여 `owsh/i18n/<lang>.json`에 있으며, `{placeholders}`를 쓸 수 있습니다.

### 7.2 버튼 (B1 앞 ○ 원, B2 가운데 △ 세모, B3 뒤 □ 네모)

| 버튼 | 짧게 누르기 (< 0.8 s) | 길게 누르기 (≥ 1.5 s) | 두 번 누르기 (간격 < 0.4 s) |
|---|---|---|---|
| B1 ○ | 글자 읽기 (OCR) | 마지막 메시지 반복 | — |
| B2 △ | 장면 설명 | 여기가 어디인지 (휴대폰 위치) | 누가 있는지 (얼굴) |
| B3 □ | 상태 안내 | 3초 누르고 있기: SOS 카운트다운 | 음성 음소거 전환 (P3–P4) |

타이밍: 0.8초에서 길게 누르기 기준 사이의 누르기는 무시합니다. B3의 길게 누르기는 3초이며, 누르고 있는 동안 실행됩니다.
받아들인 모든 버튼 입력에는 즉시 `tick`을 줍니다. SOS 카운트다운 중에는 아무 버튼이나 누르면 취소됩니다.

**안전하게 끄기:** **B1 ○ + B3 □를 함께 5초 누르고 있기**(두 버튼을 1초 안쪽으로 함께 누름) → 음성
"Shutting down"(전원을 끕니다.) + `ready` 패턴을 거꾸로(R→C→L) → 3초 뒤 전원 끔. 두 버튼을 함께 누르고 있는 동안에는
B3의 SOS 길게 누르기와 B1의 길게 누르기가 막히며, 둘 중 하나라도 일찍 떼면 취소됩니다.

### 7.3 SOS

1. 시작 조건: B3를 3초 누르고 있기, 또는 FALL.
2. 10초 카운트다운: `sos_countdown` + 음성 "Emergency alert in 10 seconds. Press any button to cancel."
   (10초 뒤 긴급 신고를 보냅니다. 취소하려면 아무 버튼이나 누르세요.)
3. 취소하지 않으면: BLE로 `sos`를 보내고(휴대폰이 확인(ack)할 때까지 5초마다 반복), 음성 "Sending emergency alert"
   (휴대폰으로 긴급 신고를 보내는 중입니다.). "Emergency alert sent"(긴급 신고를 보냈습니다.)는 휴대폰의 `ack`를 받은 뒤에만 말합니다.
4. 휴대폰 앱: 큰 경보음 + 진동, 위치 표시, 큰 버튼 "긴급 전화 걸기"
   (국가별 설정: 112 / 119 / 911 …)와 "보호자에게 문자 보내기"(지도 링크가 미리 채워짐).
   웹 플랫폼에서는 사용자(또는 주변 사람)가 통화/문자를 확인해야 합니다. 네이티브 앱은 자동화할 수 있습니다(로드맵).
5. 휴대폰이 연결되어 있지 않으면: 10초마다 음성 "Phone not connected"(휴대폰이 연결되지 않았습니다), 주변 사람이 알아차리도록
   `sos_countdown` 패턴을 60초간 계속합니다(LED 빠르게 깜빡임). 아무 버튼이나 누르면 취소됩니다.

## 8. 헬멧 ↔ 휴대폰 통신 규약 (BLE, Nordic UART Service)

- 서비스 `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- RX (휴대폰 → 헬멧, write / write-without-response) `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- TX (헬멧 → 휴대폰, notify) `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- 장치 이름: `OWSH-XXXX` (블루투스 MAC 주소의 마지막 16진수 4자리).
- 프레이밍: `\n`으로 끝나는 UTF-8 JSON 객체. 협상된 MTU − 3보다 긴 메시지는 여러 조각으로 나누어 보내고,
  받는 쪽은 `\n`이 올 때까지 모아 둡니다. 메시지 최대 1024바이트.
- 모든 메시지에는 `"t"`(종류)와 `"v": 1`(규약 버전)이 있습니다. 헬멧이 보내는 메시지에는 `"ts"`(유닉스 ms)가 있습니다.

### 8.1 헬멧 → 휴대폰

| t | 필드 | 보내는 때 |
|---|---|---|
| `hello` | `fw`, `lang`, `features` [list] | 연결 시 |
| `status` | `uptime_s`, `cpu_temp_c`, `fps`, `faults` [list], `muted` | 10초마다, 그리고 변경 시 |
| `alert` | `id`, `level` 0–4, `kind` (`obstacle`,`drop`,`step_up`,`approach`,`face`,`sign`,`fault`), `dir` (`left`,`center`,`right`,`all`), `dist_m`?, `label`?, `text` | P3 이상의 음성/진동 경고마다 |
| `speech` | `text`, `level` | 말한 모든 내용 (앱의 접근성 기록용) |
| `sos` | `id`, `reason` (`button`,`fall`), `state` (`countdown`,`sent`,`cancelled`) | SOS 진행 |
| `need_location` | — | B2 길게 누르기 |
| `pong` | `id` | ping에 대한 응답 |

### 8.2 휴대폰 → 헬멧

| t | 필드 | 효과 |
|---|---|---|
| `loc` | `lat`, `lon`, `acc_m`, `addr`? | 최신 위치; `addr`가 있으면 "여기가 어디인지"에서 말함 |
| `ack` | `id` | `sos` 수신 확인 |
| `say` | `text`, `level` (기본 3) | 헬멧을 통해 텍스트를 말함 |
| `cfg` | `lang`?, `muted`?, `volume`? (0–100), `dropoff_sensitivity`? (`low`,`normal`,`high`) | 실행 중 설정 변경 |
| `ping` | `id` | 연결 확인 |

알 수 없는 종류는 무시합니다(향후 호환성).

`status`에는 `undervoltage`와 `throttled`(불리언, 알 수 없으면 생략)도 들어 있습니다.

### 8.3 보안
- 헬멧은 **암호화되고 본딩된(bonded)** BLE 연결을 요구합니다: RX는 `encrypt-write`, TX는
  `encrypt-read` + `encrypt-notify`입니다(Just Works 페어링 — 헬멧에는 화면이 없음). 처음 연결할 때 휴대폰 OS가
  표준 페어링 대화상자를 보여 줍니다.
- `ble.bonded_only: true`(기본값): 본딩되지 않은 장치의 메시지는 버립니다. 본딩된 휴대폰이 없는 동안에는 페어링이
  열려 있고, 그 뒤에는 부팅할 때마다 120초 동안만 열립니다. 새 페어링은 음성으로 알립니다.
- 안전을 낮추는 `cfg` 변경은 항상 P2로 소리 내어 확인합니다(음소거 중에도 들림): 음소거 켜기,
  낙차 감지 민감도 low, 음량 30 % 미만 설정.
- 휴대폰의 `say`는 P2로 제한되고(P0/P1 음성을 절대 끊지 못함) 3초에 1개로 속도가 제한됩니다.

firmware/

  owsh/vision/ocr.py        # RapidOCR optional
  owsh/sensors/tfluna.py    # I2C driver (smbus2) + simulated

위 트리의 파일 이름과 주석은 코드와 맞추기 위해 영어 그대로 둡니다. 주요 설명:
`config/default.yaml` = 이 설계서의 모든 임계값, `app.py` = 스레드·버스·판정기·감시기 연결,
`arbiter.py` = 위험 → 진동 패턴·음성 결정과 재알림 대기, `reflex.py` = 구간 로직(5.1) + 단차 로직(5.2),
`protocol.py` = 메시지 인코딩/디코딩/분할(순수 함수, 테스트됨), `sim/dashboard.py` = 데스크톱 디버그 창
(영상, 상자, 모터 막대, 가상 라이다 슬라이더), `tests/` = pytest(판정기, 즉시 경고, 단차, 추적/TTC, 진동 믹서,
통신 규약, 버튼, 넘어짐), `scripts/setup_pi.sh` = apt + venv + config.txt I2C + systemd,
`stl/` = 렌더링 결과(CAD를 쓰지 않는 사람을 위해 저장소에 포함), `renders/` = PNG 미리보기,
`wiring/` = 배선도(SVG) + 핀 표, `app/` = PWA, `docs/en, docs/ko` = 가이드.

**시뮬레이션 모드 (`--sim`)**는 웹캠이나 동영상 파일이 있는 어느 PC에서나 실행됩니다. 라이다와 IMU는
대시보드의 슬라이더/키로 흉내 내고, 진동은 막대로 그리고 출력하며, 버튼은 키로 대신합니다
(`1`/`2`/`3` 짧게, `Shift+1..3` 또는 `q`/`w`/`e` 길게, `a`/`s`/`d` 두 번), 음성은 pyttsx3를 씁니다.
